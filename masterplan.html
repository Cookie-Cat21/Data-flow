01

Project Objective

What it builds

A complete real-time data pipeline that ingests a stream of simulated e-commerce events, processes them through a multi-layer architecture, applies business logic transformations, and surfaces insights on a live analytics dashboard — end-to-end, like a real production system.

Why it matters for the CV

Most junior candidates have either batch pipelines OR streaming, rarely both. This project bridges that gap: a single, coherent system that spans ingestion, streaming, batch transformation, orchestration, and a visual product — the full stack that companies like Sysco, WSO2, and Dialog are hiring for.

What it demonstrates

Kafka for event streaming, Databricks/Spark for distributed processing, dbt for analytical transformations on a medallion architecture, Airflow for orchestration, and Next.js for a WebSocket-fed live dashboard. Each technology appears in real job descriptions, not toy examples.

The interview talking point

Every design decision maps to a real trade-off: why Kafka over direct DB writes, why medallion architecture over a flat schema, why dbt over raw SQL, why Airflow over cron. You can defend every choice — that's the difference between a project and a portfolio piece.

Medallion Architecture: Raw events land in Bronze (exact copy, no transforms). Bronze is cleaned and typed into Silver. Business-ready aggregates and metrics live in Gold. dbt models govern the Silver→Gold layer. This pattern is the de-facto standard at companies doing serious analytics engineering.
03

Technology Stack

Ingestion

Apache Kafka

Event streaming backbone. A Python producer replays the Olist CSV at configurable speed, publishing to topics per entity (orders, payments, reviews). Consumers read with exactly-once semantics.

Confluent Cloud free tier

Processing

Databricks

Spark Structured Streaming reads Kafka topics, applies windowed aggregations, and writes micro-batches to Delta Lake. Databricks Community Edition keeps costs zero.

Delta Lake · Spark 3.x

Transform

dbt Core

Defines Silver and Gold layer models as SQL transformations with full lineage, tests, and documentation. Astronomer Cosmos runs dbt DAGs inside Airflow natively.

dbt-databricks adapter

Storage

Delta Lake

ACID-compliant table format on top of cloud object storage. Bronze, Silver, and Gold layers as managed Delta tables. Time travel enables debugging and re-runs.

ACID · Time Travel

Orchestration

Apache Airflow

DAGs schedule the full pipeline: producer trigger → Spark job → dbt run → dashboard refresh. Astronomer Cosmos integrates dbt as first-class Airflow tasks.

Astronomer Cosmos

Frontend

Next.js 14

Live dashboard with WebSocket-fed charts (Recharts). Displays GMV, order funnel, seller rankings, and delivery SLA in real time as events flow through the pipeline.

WebSocket · Recharts · Tailwind

Streaming Replay Strategy: A Python producer reads the CSVs in purchase_timestamp order and publishes events to Kafka topics at a configurable speed multiplier (e.g., 100× real time = 2 years of data in ~4 hours). This simulates a live event stream while using a static, well-understood dataset.

Build Phases

01
Foundation

Environment Setup & Data Exploration

  • Download Olist dataset, load into Pandas, understand schema and relationships
  • Set up Confluent Cloud Kafka cluster + create topics (orders, payments, reviews)
  • Provision Databricks Community workspace, configure Delta Lake paths
  • Install Airflow locally (Astro CLI) and verify DAG scaffolding
  • Initialize dbt project with dbt-databricks adapter
  • Create GitHub repo, add .gitignore and project README
Week 1–2 FOUNDATION
02
Core Pipeline

Kafka Producer + Spark Streaming → Bronze

  • Build Python Kafka producer with configurable replay speed multiplier
  • Write Spark Structured Streaming job reading from Kafka, writing to bronze Delta tables
  • Implement schema enforcement and bad-record handling (PERMISSIVE mode + dead-letter topic)
  • Validate end-to-end: produce 1K events, confirm they land in Bronze
  • Add Spark job to Airflow as DatabricksRunNowOperator task
Week 3–4 CORE
03
Transform

dbt Models — Silver & Gold Layers

  • Write stg_orders, stg_payments, stg_customers staging models (Bronze → Silver)
  • Build int_order_enriched intermediate model joining orders + payments + customers
  • Create Gold marts: fct_orders, dim_customers, dim_products, dim_sellers
  • Write business metric models: rpt_gmv_daily, rpt_delivery_sla, rpt_seller_performance
  • Add dbt tests (not_null, unique, relationships) and dbt docs generate
  • Integrate dbt DAG into Airflow via Astronomer Cosmos
Week 5–6 TRANSFORM
04
Product

Live Dashboard — Next.js + WebSocket

  • Scaffold Next.js 14 app with App Router and Tailwind CSS
  • Build Node.js WebSocket server that polls Gold tables every 5s and broadcasts diffs
  • Implement KPI cards: GMV, active orders, average delivery time, review score
  • Add Recharts line chart for GMV over time (live-updating)
  • Build seller leaderboard table and order status funnel chart
  • Deploy to Vercel (frontend) + Railway (WebSocket server)
Week 7–8 PRODUCT
05
Polish

Documentation, Testing & Demo Recording

  • Write comprehensive README.md with architecture diagram and setup guide
  • Add CI/CD with GitHub Actions: dbt test + linting on every push
  • Record 3–5 min Loom demo walking through the live pipeline end-to-end
  • Add Great Expectations data quality checks on Silver layer
  • Write architecture decision records (ADRs) for key choices
  • Pin all final versions, clean up branches, write LinkedIn announcement post
Week 9–10 POLISH
